# TDD Green

`tdd-red` 단계가 만든 실패 테스트를 입력으로, **현재 실패 중인 테스트를 통과시키는 최소한의 구현 코드**만 작성한다.
TDD 사이클의 Green — 테스트가 요구하는 동작만 충족시키고, 그 이상은 만들지 않는 것이 목표다.

- **입력**: 이슈 번호 `$ARGUMENTS` (예: `/tdd-green 6`).
- **산출물**: `src/`의 구현 코드. **테스트 파일(`*.test.ts` / `*.test.tsx`)은 수정하지 않는다.**
- **도구**: Vitest (`npm test` = `vitest run`), 커버리지는 `npx vitest run --coverage`.

## Workflow

### 1. 실패 테스트 목록 확인

`npm test`를 실행해 현재 실패 중인 테스트 목록을 파악한다.

### 2. collect 실패 감지 → stub 생성

시나리오 문서(`docs/features/{feature}/issue-{N}.md`)의 체크박스(`- [ ]`) 총 건수와 vitest가 보고하는
`Tests` 수를 비교한다. **불일치하면 import 대상 모듈이 없어 수집(collect)이 실패한 것**이므로,
**시그니처만 있는 stub 파일**을 생성해 전체 테스트가 인식되도록 한다(동작 구현은 아직 하지 않음).

### 3. 디자인 컨텍스트 로드

- `docs/design-system.md`가 있으면 읽어 구현 대상 컴포넌트의 시각적 스펙(색상·간격·레이아웃·상태별 표현)을 파악한다.
- `docs/features/{feature}/issue-{N}.md`에 "디자인 참고" 섹션이 있으면 함께 확인한다.
- `CLAUDE.md`의 스타일링 컨벤션도 참조한다.
- 디자인 문서가 없으면 이 단계를 건너뛰고 `CLAUDE.md` 컨벤션만 따른다.

### 4. 첫 번째 실패 테스트를 통과시키는 최소 구현

해당 테스트를 통과시키는 **최소한의 코드만** 작성한다.

- UI 컴포넌트는 테스트가 요구하는 동작을 충족하되, `design.md`의 스타일 스펙을 함께 적용한다.
- `design.md`에 명시된 Tailwind 클래스·레이아웃 구조·상태별 표현을 그대로 사용한다.

### 5. 실행 → 통과 + 회귀 확인 〈피드백 루프〉

`npm test`를 실행해 해당 테스트 통과와 기존 테스트 회귀 없음을 확인한다.

- 아직 실패하면: 에러 메시지를 읽고 원인을 분석해 코드를 수정한 뒤 **5번을 다시 실행**한다(최대 **5회** 반복).
- 5회 반복 후에도 실패하면: 개발자에게 실패 원인을 보고하고 **중단**한다.

### 6. 시나리오 문서 항목 체크

`docs/features/{feature}/issue-{N}.md`의 해당 항목을 `[x]`로 체크한다.

### 7. 다음 실패 테스트로 이동

다음 실패 테스트로 넘어가 **4번부터 반복**한다.

### 8. 전체 통과 후 커버리지 측정

```bash
npx vitest run --coverage
```

- 미커버 라인을 확인해 **시나리오에서 빠진 케이스인지 개발자에게 보고**한다.
- **커버리지를 올리기 위한 테스트 추가는 금지.** 참고용으로만 활용한다.

### 9. 결과 요약

통과한 테스트, 작성한 구현, 미커버 라인, 보고 사항을 요약한다.

## Guidelines / Constraints

- **테스트에 없는 기능은 구현 금지** — 테스트가 요구하는 동작만 만든다.
- **테스트 파일 수정 금지** — `*.test.ts` / `*.test.tsx`는 건드리지 않는다.
- **불필요한 추상화 금지** — Green 단계는 통과가 목적, 일반화는 Refactor에서.
- `design.md`의 스타일은 적용하되, **`design.md`에 없는 시각적 요소를 임의로 추가하지 않는다.**
- 입력은 이슈 번호(`$ARGUMENTS`).

## Output

- `src/`의 최소 구현 코드 — 실패 테스트를 통과시키는 만큼만.
- `npm test` 결과: 대상 테스트 통과 + 기존 테스트 회귀 없음.
- 커버리지 리포트 기반 미커버 라인 보고(테스트 추가는 하지 않음).
- 다음 단계: 중복·구조 정리(**Refactor**).
