# 태그 기능 PRD

> 본 문서는 [`spec-fixed.md`](./spec-fixed.md)(확정 정의서)를 기반으로 한 제품 요구사항 문서(PRD)의 뼈대다.
> **기술 결정(ADR)** 섹션은 의도적으로 비워둔 상태이며, 다음 세션에서 논의·확정한다.

---

## 1. 개요

노트에 태그를 추가·삭제·표시할 수 있게 하여, 노트를 분류하기 위한 메타정보를 제공한다.

- **대상 사용자**: 노트 앱 사용자
- **핵심 가치**: 노트에 가벼운 분류 메타데이터를 부여해 향후 검색·필터링의 기반을 만든다.
- **이번 스코프 범위**: `NoteEditor`에서의 태그 입력/삭제/표시까지. 검색·필터링·전역 태그 관리는 제외(→ [4. Out of Scope](#4-out-of-scope)).
- **데이터 모델**: `Note` 타입에 `tags: string[]` 필드 추가(비정규화, 기본값 `[]`).
- **저장 방식**: 태그 변경은 노트 본문 저장과 함께 기존 `updateNote` API로 일괄 처리(별도 태그 API 없음).

## 3. 기술 결정 (ADR)

> 아키텍처 **안 C(`useTagInput` 커스텀 훅 + 영속화 주입)** 를 채택한 전제로 정리한다.
> 핵심 발상: **태그 상태·검증 규칙을 순수 훅에 캡슐화**하고, 영속화(언제 서버에 쓰는가)는 훅 바깥에서 콜백으로 주입해 분리한다.

### ADR-1. 태그 저장 구조 (비정규화 `tags: string[]` vs 정규화 컬렉션)

- **Context**: 노트는 JSON Server(`db.json`)에 단일 컬렉션으로 저장된다. 태그는 분류용 메타이고, 이번 스코프에 검색·전역 태그 관리가 없다([4. Out of Scope](#4-out-of-scope)). 데이터 규모가 작고 강의용 실습이다.
- **Decision**: `Note` 타입에 `tags: string[]`를 추가하고 **노트 문서 내부에 비정규화**해 저장한다. 별도 `tags` 컬렉션이나 노트-태그 관계 테이블을 만들지 않는다. 기본값은 빈 배열 `[]`.
- **Alternatives**:
  - (a) 정규화 — 별도 `/tags` 컬렉션 + 노트에 `tagIds: string[]`. 전역 rename·집계엔 유리하나 JSON Server에서 조인/정합성 관리 비용이 크고 이번 스코프 초과.
  - (b) 태그를 `content`에 인라인 마크업(`#tag`)으로 묻기 — 파싱 취약, 검증 규칙 적용 불가.
- **Consequences**:
  - ✅ API 변경 최소 — `updateNote(id, Partial<Note>)`가 `{ tags }`를 그대로 PATCH로 흡수(`src/api/notes.ts` 무변경). 훅도 `note.tags`를 직접 읽으면 됨.
  - ✅ 안 C의 `useTagInput`이 단일 배열만 다루면 되어 단위 테스트가 단순.
  - ⚠️ 전역 태그 기능(rename·자동완성)이 생기면 비정규화 데이터를 순회·갱신해야 함 → 그때 마이그레이션으로 정규화 전환(ADR-2와 동일 전략).

### ADR-2. 기존 노트 마이그레이션 전략 (`tags` 기본값 채우기)

- **Context**: `db.json`의 기존 노트에는 `tags` 필드가 없다. 타입에 `tags: string[]`(non-optional)를 추가하면 기존 데이터와 타입이 어긋난다. 별도 마이그레이션 스크립트를 돌리는 인프라는 없다.
- **Decision**: **읽기 시점 폴백(lazy default)** 을 채택한다. 데이터를 강제로 일괄 변환하지 않고, 훅·컴포넌트가 `note.tags ?? []`로 안전하게 읽는다. 노트를 한 번이라도 저장하면 그 시점에 `tags`가 정식 필드로 영속화된다(write-through).
- **Alternatives**:
  - (a) 일괄 마이그레이션 — `db.json`을 스크립트로 전수 `tags: []` 주입. 1회성 작업이지만 실습 환경에서 매번 시드가 갈려 번거롭고, seed/런타임 db 동기화 이슈.
  - (b) `tags?: string[]`(optional)로 선언 — 호출부마다 `undefined` 분기가 번지고 검증 로직이 지저분해짐.
- **Consequences**:
  - ✅ 마이그레이션 스크립트·다운타임 없음. 기존 노트도 즉시 정상 표시(빈 태그 영역).
  - ✅ `useTagInput`의 초기값을 `note.tags ?? []` 한 줄로 처리 → 엣지케이스 테스트 간단.
  - ⚠️ 한동안 db에 `tags` 있는 노트와 없는 노트가 혼재 → 읽는 모든 경로에서 `?? []` 폴백을 빠뜨리면 안 됨(린트/리뷰로 강제). 타입은 non-optional로 두되 경계(API 응답 매핑)에서 한 번만 정규화하는 것을 권장.

### ADR-3. 저장·동기화 방식 (본문과 일괄 저장 vs 별도 태그 API)

- **Context**: 현행은 "폼 로컬 상태(`NoteEditor`)에 모았다가 저장 버튼에서 Context 액션으로 커밋"하는 3계층 패턴이다. `NotesContext`는 낙관적 업데이트 없이 API 응답으로 `setNotes`. spec의 "저장/동기화"는 **본문과 일괄 저장**을 명시하나, 향후 즉시 저장 요구가 나올 수 있다.
- **Decision**: 안 C대로 **`useTagInput` 훅을 영속화로부터 분리**한다. 훅은 메모리상의 태그 배열과 검증만 책임지고, 서버 반영 시점은 알지 못한다. 영속화는 **주입된 콜백**으로 처리하며, **기본 구현은 spec 준수(본문과 일괄 저장)** — 저장 버튼에서 기존 `updateNote(id, { title, content, tags })` / `createNote(title, content, tags)` 한 번으로 커밋한다. 별도 태그 전용 API는 만들지 않는다.
- **Alternatives**:
  - (a) 즉시 저장 — Context에 `addTag/removeTag`를 두고 칩 변경마다 PATCH(안 B). 미저장 신규 노트(`isCreating`, id 없음)에서 경로가 갈라지고 낙관적 업데이트 부재로 칩마다 네트워크 지연 노출.
  - (b) 태그 전용 엔드포인트 — spec이 금지(별도 API 없음), 트랜잭션 경계만 복잡해짐.
- **Consequences**:
  - ✅ spec 충실 + 기존 "저장 버튼" 멘탈모델·3계층 분리 유지. `createNote`만 `tags` 인자 확장이 필요(`NotesContext.createNote` 시그니처).
  - ✅ 영속화가 콜백 뒤에 숨어 **나중에 즉시 저장으로 교체 시 훅·컴포넌트 변경 없이 콜백만 교체**. 결정 번복 비용이 낮음.
  - ✅ 단위 테스트에서 영속화를 mock 콜백으로 주입 → 네트워크 없이 "확정 시 onChange 호출됨"만 검증.
  - ⚠️ 즉시 저장이 정식 요구가 되면 콜백 교체 + 신규 노트 id 확보 흐름을 추가 설계해야 함(현재는 일괄이라 비해당).

### ADR-4. 중복 비교 및 정규화 정책 (대소문자 무시 비교 / 원본 보존 저장)

- **Context**: spec 검증 규칙 — 중복은 대소문자 무시 비교(`React` == `react`), 저장은 원본 표기 보존, 입력은 `trim()` 후 빈 문자열 차단, 1개 최대 15자, 노트당 최대 10개, Backspace로 마지막 칩 삭제. 이 규칙들이 흩어지면 UI와 검증이 불일치하기 쉽다.
- **Decision**: 위 규칙 전부를 **`useTagInput` 훅 한 곳에 순수 함수로 집중**한다. 비교는 `tag.trim().toLowerCase()` 기준으로 하되 배열에는 **trim된 원본 표기**를 저장한다. `addTag`는 (trim → 빈값 차단 → 길이 15자 차단 → 소문자 중복 검사 → 개수 10개 차단) 순서로 게이트한다. 한도 도달 시 조용히 무시(에러 메시지 없음, input만 비움).
- **Alternatives**:
  - (a) 저장 시 소문자로 정규화해 보관 — 표기(`React`)가 사라져 UX 저하. spec 위반.
  - (b) 검증을 컴포넌트(`ChipInput`)에 인라인 — 안 A 성격. 로직 테스트에 DOM 렌더가 필요해 무겁고 규칙 누락 위험.
  - (c) 라이브러리(예: tag-input 패키지) 도입 — 규칙이 단순·고정이라 의존성 과함.
- **Consequences**:
  - ✅ 모든 엣지케이스를 `renderHook(useTagInput)`로 **DOM 없이 단위 테스트** — 대소문자 중복, trim 공백, 15자/10개 경계, Backspace 삭제를 표로 검증.
  - ✅ `ChipInput`은 키 이벤트를 훅 액션(`addTag`/`removeTag`/`removeLast`)으로 위임만 하는 dumb 컴포넌트 → 재사용·E2E 단순.
  - ⚠️ 비교 정규화가 `toLowerCase()` 단순 방식이라 유니코드 케이스폴딩/공백 변형(전각 등)은 비대상 — 이번 스코프 한도로 명시.

## 4. Out of Scope

이번 스코프에서 **명시적으로 제외**하는 항목. 향후 별도 PRD/스코프로 다룬다.

### 4.1 검색 · 필터링

- 태그로 노트를 검색하는 기능.
- 태그 클릭 시 해당 태그가 달린 노트만 필터링하는 기능.
- 다중 태그 AND/OR 조합 필터.
- 태그 기반 정렬.

### 4.2 노트 목록(`NoteItem`)에서의 태그 표시

- `NoteItem`(사이드바 목록)에는 태그 칩을 **표시하지 않는다**. 표시는 `NoteEditor`(상세/편집 화면)로 한정.

### 4.3 전역 태그 관리

- 전역 태그 목록 화면(전체 태그 모아보기).
- 태그 입력 시 **자동완성/추천**.
- 태그 **이름 일괄 변경(rename)** 및 변경 전파.
- 사용되지 않는 태그 정리(orphan 정리).
- 태그별 사용 횟수 집계/통계.

### 4.4 데이터 모델 고도화

- 정규화 구조(별도 `tags` 컬렉션, 노트-태그 관계 테이블)로의 전환.
- 태그에 **색상·아이콘·설명** 등 메타데이터 부여.
- 태그 **계층 구조**(상위/하위 태그, 네임스페이스).

### 4.5 협업 · 동기화

- 태그에 대한 별도 저장 API(노트 본문과 분리된 태그 전용 엔드포인트).
- 낙관적 업데이트(Optimistic UI) — 기존 방침대로 응답값으로 갱신.
- 다중 사용자 동시 편집 시 태그 병합/충돌 처리.

### 4.6 입력 방식 확장

- 드래그 앤 드롭으로 태그 순서 변경.
- 붙여넣기(쉼표 구분 문자열) 일괄 태그 등록.
- 태그 자동 분류/추천(AI 등).

## 5. 용어 정의

| 용어                | 정의                                                                                                           |
| ------------------- | -------------------------------------------------------------------------------------------------------------- |
| **태그(Tag)**       | 노트에 부여하는 짧은 분류용 문자열. `Note.tags: string[]`의 한 원소. 1개당 최대 15자.                          |
| **칩(Chip)**        | 확정된 태그를 시각적으로 나타내는 pill 형태의 UI 요소. hover 시 × 삭제 버튼이 노출된다.                        |
| **Chip Input**      | 텍스트 input과 확정된 칩 목록을 한 영역에 결합한 입력 컴포넌트. `NoteEditor` 제목 입력란 바로 아래에 위치.     |
| **확정(Commit)**    | input의 입력값을 칩으로 변환하는 동작. `Enter` 또는 쉼표(`,`) 키로 트리거.                                     |
| **trim**            | 입력값 앞뒤 공백 제거. trim 결과가 빈 문자열이면 태그로 추가하지 않는다.                                       |
| **중복(Duplicate)** | 이미 존재하는 태그와 **대소문자를 무시**했을 때 같은 값(`React` == `react`). 중복은 에러 없이 무시.            |
| **원본 보존 저장**  | 비교는 소문자로 하되, 저장은 사용자가 입력한 **원본 표기 그대로**(예: 먼저 `React`로 입력하면 `React`로 저장). |
| **마이그레이션**    | 기존 노트(`tags` 필드 없음)에 빈 배열(`[]`)을 채워 신규 스키마에 맞추는 작업.                                  |
| **스코프(Scope)**   | 이번 작업에서 구현하기로 한 범위. 범위 밖은 [Out of Scope](#4-out-of-scope) 참조.                              |
